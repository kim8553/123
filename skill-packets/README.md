# 스킬 패킷 비교 — 확인한 것과 확인하지 못한 것

2026-09-22 기준, 제공받은 서버 아카이브의 자료만 사용한 **읽기 전용** 분석입니다. 분석 코드와 요약 결과에 원본 PCAP, 서버 실행 파일, 원본 스킬 데이터, IP 주소, 계정/캐릭터 식별자 및 전송 페이로드 전체를 넣지 않았습니다.

## 검증 가능한 결과

- 공식 서버 측으로 식별된 두 캡처의 디코딩된 `frames.log`에서 서버→클라이언트(`S2C`) 스킬 알림 `0x1E` / `msgID=205` **2,115프레임**을 확인했습니다. 그중 **2,115프레임 전부**에서 `TVar` 인자 4개(첫 항목인 메시지 ID 포함), 메시지 ID `205`, 뒤따르는 `object8`, NUL 종료 스킬 ID 문자열, `object8`을 확인했습니다. 스킬 ID가 ASCII인 이 프레임의 전체 크기는 `32 + 스킬 ID의 ASCII 바이트 수`입니다. 이는 *공식 캡처에서 관찰된 형태*이며 프로토콜 전체의 보편적 규칙을 주장하지 않습니다.
- 현재 서버의 프로세스 로그에서 스킬 사용 승인 이벤트 **2,162건**, 클라이언트 CustomSend `msg_id=211`로 해석된 이벤트 **5,019건**을 확인했습니다. 양쪽 자료에 **같은 이름으로 등장하는 스킬 ID는 42종**입니다. 캡처 시점·캐릭터·상황이 서로 달라 같은 사건을 짝지은 수치는 아닙니다.
- 예시 `CS_jh_chz04`: 공식 캡처에서 `msgID=205` 알림 **126프레임(각 43바이트)**을 확인했습니다. 현재 서버 로그에는 해당 스킬 **사용 승인 42건**, 클라이언트→서버 `msg_id=211` 디코딩 **115건**이 있습니다. 하지만 현재 서버가 이 스킬에 대해 `msgID=205`를 실제 송신했는지는 송신 패킷 기록이 없어 검증하지 못했습니다.
- 이름이 `capture-localsrv/cap.pcapng`인 **제공된 현재 서버 측 캡처**는 TCP 세그먼트 **2,509개**를 포함하지만 **애플리케이션 데이터가 포함된 TCP 세그먼트는 0개**입니다. 따라서 이 파일에서는 서버→클라이언트 스킬 패킷을 추출할 수 없습니다.

## 결론 및 제한

**공식 서버와 현재 서버의 패킷이 일치한다는 주장도, 스킬 패킷 불일치가 확정됐다는 주장도 검증되지 않았습니다.** 공식 서버 발동 알림의 관찰 가능한 스키마를 확정했을 뿐, 현재 서버가 동일 스킬에 대해 보낸 원본 패킷을 확보하지 못했습니다. 현재 서버 로그의 `accepted skill`은 **전송 패킷이 아닙니다**. 공식 서버의 같은 조건·동일 동작에 대응하는 C2S `211` 메시지 필드도 비교하지 못했습니다. 이전 `5675` 스킬 설정 실험용 패치와 본 패킷 분석은 별개이며 해당 패치를 적용할 근거가 생기지 않았습니다.

후속 검증에는 동일한 스킬·조건의 **양측 송수신 데이터 패킷**이 필요합니다. IP/계정/캐릭터 데이터는 공유 보고서에 넣지 말고, 본인에게 접근 권한이 있는 테스트 환경에서만 캡처하십시오.

## 재현

```bash
python skill_packet_parity.py /path/to/server_nested.zip --output parity_report.json
python -m unittest -v test_skill_packet_parity.py
```

보고서 `skill_packet_parity_report.json`은 소스 파일 SHA-256와 판정 한계를 포함합니다. 스크립트는 ZIP을 읽기만 하며 네트워크 접속·게임 실행·EXE 및 스킬 데이터 수정·패킷 주입을 하지 않습니다.
